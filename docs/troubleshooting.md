# 排障记录（Troubleshooting Log）

> 方法论：**症状 Symptom → 假设 Hypothesis → 证据 Evidence → 处置 Action**。
> 每条记录四步齐全；证据必须来自命令输出，不靠猜。

## 案例 01：端口被占，服务起不来（2026-10-23 · WSL/Ubuntu）

- **症状**：服务无法绑定 8000 端口，需要定位占用者。
- **假设**：已有进程占住了 8000。
- **证据**：`ss -tlnp | grep 8000` 输出：

  ```text
  LISTEN 0 5 0.0.0.0:8000 0.0.0.0:* users:(("python3",pid=13887,fd=3))
  ```

- **处置**：`kill 13887`（先礼：SIGTERM，允许进程清理现场）；若不理会再 `kill -9`（后兵：SIGKILL，内核直接收尸，无法拦截）。
- **结果**：复跑 `ss -tlnp | grep 8000` 空输出，端口释放，服务可正常启动。
- **教训**：排障链 = 症状出发 → 命令拿证据 → 处置 → 复验。与 Windows 侧（P0.04）完全同构，只是命令方言不同。

## 信号速记

| 信号    | 编号 | 含义                        | 能否被进程拦截             |
| ------- | ---- | --------------------------- | -------------------------- |
| SIGTERM | 15   | 礼貌请求退出（`kill` 默认） | 能（可清理现场，也能无视） |
| SIGKILL | 9    | 内核强制处决（`kill -9`）   | **不能**                   |

## 命令速查：Windows → Linux

| 干什么       | Windows（P0.04）              | Linux（P0.16）                                |
| ------------ | ----------------------------- | --------------------------------------------- |
| 看进程快照   | Get-Process                   | ps aux                                        |
| 端口反查进程 | netstat -ano \| findstr :端口 | ss -tlnp \| grep 端口                         |
| 杀进程       | Stop-Process -Id \<pid\>      | kill \<pid\>（先礼）/ kill -9 \<pid\>（后兵） |
| 实时监控     | 任务管理器                    | top                                           |
| 进程档案     | —（无对应物）                 | /proc/\<pid\>/（cmdline、status、exe…）       |
